## 1. 背景

Runtime Completion 完成后，Modelry 已具备真实 Runtime、CLI、Admin、HTTP、MCP、SQLite、Migration、Auth、File、Hook、Realtime 等核心能力，但首次使用仍要求显式执行：

```text
modelry init
modelry serve
```

同时早期 Project Source 使用 `modelry/`，会与放在 Project Root 中的 standalone executable `modelry` 同名冲突。

V0.1.0 的首次使用目标应收敛为：

```text
下载 modelry
→ 放入 Project Root
→ ./modelry
→ 自动初始化
→ 自动启动 Runtime
→ 输出 Admin URL / Setup Token
→ 打开 Admin
```

因此需要 Zero-Config Startup，并保证初始化具备原子性、幂等性以及清晰的错误边界。

## 2. 目标

1. 无参数 `modelry` 在空 Project Root 中自动完成初始化并启动 Runtime。
2. 保留 `modelry init` / `modelry serve` 显式控制路径。
3. Project Source 从 `modelry/` 调整为 `.modelry/`。
4. 初始化失败不得留下 partial Project。
5. 区分 empty / initialized / partial 三种 Project 状态。
6. partial Project 不得静默修复。
7. 完整但配置非法的 Project 继续进入既有 Runtime Config validation。
8. `modelry serve` 对未初始化 Project 保持严格拒绝。
9. `-h` / `--help` / `help` 必须无副作用。
10. 保持 Frozen HTTP Contract 不变。

## 3. 默认 Project 布局

```text
<project>/
├── modelry.config.json
├── .modelry/
│   ├── migrations/
│   ├── hooks/
│   └── schema.snapshot.json
├── data/
└── .gitignore
```

Project Root 可以同时存在：

```text
<project>/modelry
<project>/.modelry/
```

前者可以是 standalone executable，后者是 Project Source。

默认路径统一调整：

```text
modelry/migrations/           → .modelry/migrations/
modelry/hooks/                → .modelry/hooks/
modelry/schema.snapshot.json  → .modelry/schema.snapshot.json
```

V0.1.0 不引入旧 `modelry/` 路径 dual-read / dual-write 兼容层。

## 4. 启动语义

### 4.1 无参数启动

执行：

```text
./modelry
```

行为：

- empty Project：atomic init → serve；
- initialized Project：直接 serve；
- partial Project：拒绝，不自动 repair；
- invalid config：进入已有 config validation，不伪装成 partial。

第二次无参数启动不得重复初始化或重写 Project Source。

### 4.2 显式 init

`modelry init`：

- 只创建 Project Source；
- 不启动 Runtime；
- 不创建 Runtime Data；
- 必须幂等；
- initialized Project 再次执行不得改写 source；
- partial Project 必须失败。

### 4.3 显式 serve

`modelry serve`：

- 只启动已初始化 Project；
- empty Project 必须严格失败；
- partial Project 必须严格失败；
- 不得隐式执行 init。

因此：

```text
modelry
= convenience path

modelry init + modelry serve
= explicit/scriptable path
```

## 5. Project 初始化状态

Runtime 必须区分：

```text
empty
initialized
partial
```

### empty

未发现 Modelry Project Source marker。

允许：

- `modelry init`
- 无参数 `modelry` 自动初始化。

### initialized

完整 Source 存在：

- `modelry.config.json` 是 regular file；
- `.modelry/` 存在；
- `.modelry/migrations/` 存在；
- `.modelry/hooks/` 存在；
- `.gitignore` 是 regular file；
- `.gitignore` 含 `data/`；
- 不存在 legacy `modelry/` directory 冲突。

### partial

已经出现部分 Source marker，但布局不完整，例如：

- 只有 config；
- 只有 `.modelry/`；
- migrations/hooks 缺失；
- `.gitignore` 缺 `data/`；
- 存在 legacy `modelry/` directory。

partial Project：

- 不自动修复；
- init 失败；
- no-command startup 失败；
- 返回明确的 incomplete source error；
- details 应指出缺失项。

## 6. Config Validity 与 Source Completeness 分离

完整 Source + 非法 config：

```text
state = initialized
configValid = false
```

必须继续进入既有 Runtime Config validation。

不能把配置错误错误归类为 partial source。

## 7. Atomic Init

初始化必须满足：

```text
完整成功
或
回到初始化前状态
```

不得留下：

- 半写入 config；
- 半创建 `.modelry/`；
- 被破坏的 `.gitignore`；
- staging directory；
- Runtime Data。

初始化应先在 Project Root 内准备 staging 内容：

- `.modelry/migrations/`
- `.modelry/hooks/`
- `modelry.config.json`
- 合并后的 `.gitignore`

然后按可回滚顺序提交。

故障回归至少覆盖：

```text
during-source-prepare
after-config-commit
before-gitignore-commit
after-gitignore-commit
```

失败后必须：

- 删除本次新增 source；
- 删除本次新增 config；
- 恢复已有 gitignore；
- 删除 staging；
- 不创建 data；
- 再次检查为 empty。

## 8. Init 幂等性

连续执行两次：

```text
modelry init
```

第二次必须：

- 成功；
- 不重写 `modelry.config.json`；
- 不重复追加 `data/`；
- 不清空 migrations；
- 不清空 hooks；
- 不创建 Runtime Data；
- 不创建假的 schema snapshot。

无参数 `modelry` 第二次运行同样不得改写 Source。

## 9. Project Source 与 Runtime Data 边界

仅执行：

```text
modelry init
```

后应该存在：

```text
modelry.config.json
.modelry/migrations/
.modelry/hooks/
.gitignore
```

不应该存在：

```text
data/modelry.db
.modelry/schema.snapshot.json
```

Runtime Data 和 snapshot 继续由真实 Runtime 生命周期产生。

## 10. .gitignore 语义

初始化必须保证：

```text
data/
```

存在且只出现一次。

已有 `.gitignore`：

- 保留原内容；
- 缺失时追加 `data/`；
- 初始化失败时恢复原内容。

没有 `.gitignore`：

- 创建；
- 初始化失败时删除。

## 11. Help / CLI UX

以下命令必须正常工作：

```text
modelry -h
modelry --help
modelry help
```

帮助输出至少说明：

- CLI Usage；
- 主要 command；
- 无参数运行会自动初始化并启动；
- `init` / `serve` 的显式用途。

Help 必须无副作用：

- 不创建 config；
- 不创建 `.modelry/`；
- 不创建 data；
- 不修改 `.gitignore`。

`--project` 继续作为显式 Project Root 覆盖入口。

## 12. Structured Error

### Empty + explicit serve

必须返回产品级错误：

```text
reason = project_not_initialized
```

或冻结语义等价值，而不是把 ENOENT / ENOTDIR 等底层异常直接暴露为首要错误。

### Partial source

必须返回类似：

```text
Project contains an incomplete Modelry source layout
```

并带：

- Project Root；
- missing markers；
- actionable hint。

## 13. Cross-Platform 要求

实现和测试必须：

- 使用平台安全 path API；
- 不硬编码 POSIX separator；
- 不硬编码 `/tmp`；
- Windows 使用 `modelry.exe`；
- 非 Windows 使用 `modelry`；
- chmod 仅用于非 Windows；
- Project Source 与 executable co-location 在 Windows/POSIX 均成立。

## 14. User Stories

1. 新用户可以直接运行 `modelry` 完成首次初始化和启动。
2. standalone executable 可以与 Project Source 同目录共存。
3. 自动化脚本仍可使用 `init -> serve` 两阶段控制。
4. 初始化失败不会留下半初始化 Project。
5. 重复 init/start 不会破坏已有 Source。
6. partial Project 不会被系统偷偷修补。
7. Config Error 与 Source Layout Error 保持可区分。
8. Help 命令不会修改用户项目。
9. Windows / POSIX 均不存在路径硬编码依赖。

## 16. 非目标

本 Spec 不负责：

- 新增 Runtime 业务能力；
- 修改 Frozen HTTP Contract；
- 引入 legacy path 自动迁移；
- 引入 dual-read / dual-write；
- S3；
- Backup / Restore；
- Cluster / HA；
- Multi-project；
- 其他 V0.1.x deferred 能力。

## 17. Definition of Done

Spec 0006 只有以下全部成立才视为完成：

- 无参数 startup 可从空目录进入 READY；
- executable 与 `.modelry/` 可共存；
- init 原子、幂等；
- partial Project 被明确拒绝；
- invalid config 使用既有 config validation；
- explicit serve 不自动初始化；
- help 无副作用；
- Project Source 路径统一为 `.modelry/`；
- standalone/dev/blog/runtime tests 已同步；
- Windows/POSIX 路径逻辑无硬编码问题；
- Frozen Contract diff = 0；
- typecheck / lint / tests / build / smoke 通过。

```text
./modelry
```
