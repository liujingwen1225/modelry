# Spec 0004：Modelry V0.1.0 Data Plane Core 实施规格

- **状态：** 已实现 — 已合并到 `develop`
- **阶段：** `closure`
- **目标版本：** V0.1.0
- **前置条件：** Model Evolution Core 已完成并合并至 `develop`
- **对应实现 Issue：** #67、#68、#69、#70、#71、#72

## 1. 目的

本规格定义 Modelry V0.1.0 下一阶段 **Data Plane Core Closure** 的实施边界。

当前 Model Evolution Core 已完成 Backend Model、ChangeSet、Diff/Risk/Preconditions、Apply、Project Migration、SQLite Physical Schema、Runtime Backend Model、Schema Snapshot 的真实闭环。

下一阶段必须让已经 Apply 的 Collection 真正成为可持久化、可查询、可授权访问的业务数据后端。

本阶段最终成功链路为：

```text
Runtime Backend Model
→ SQLite Business Record Store
→ Administrative Record CRUD
→ Unified Expression Engine
→ Filter / Sort / Pagination
→ Application Data API
→ Record Policy
→ Relation Write / Options / Expand
→ Admin Records Real Backend
```

本规格不重新设计 Frozen Contract，不重新定义 Backend Model，不引入第二套数据模型、查询语言、Policy 语言、Auth transport 或数据库抽象。

## 3. 当前问题

当前 `develop` 已能真实创建和演进 Collection 的物理结构，但 Records 运行面仍未闭合：

- Production Record list/get/create/update/delete 仍依赖 Mock Record Repository；
- Backend 新建 Collection 不存在于 Mock Store 时，Record list 仍有 `NOT_FOUND -> []` 临时桥；
- `recordService` 仍有对 Mock Collection fixture 的依赖；
- Relation Options 仍从 Mock Record 数据派生；
- Application Data Plane 的真实 Record CRUD / Query / Policy Runtime 尚未闭合。

因此当前状态是：

```text
真实 Backend Model / SQLite Schema
            ↓
         运行断层
            ↓
Mock Records / Mock Query / Mock Policy
```

---

## 4. 总体解决方案

建立唯一真实 Record 主路径：

```text
Runtime Backend Model
      ↓
Record Application Service
      ↓
Expression / Policy / Query
      ↓
Record Store
      ↓
SQLite Runtime Store
```

Administrative Data Access 与 Application Data Plane 共享 Record Store / Query Engine，但授权入口严格分离：

```text
Admin / Agent
→ Capability Scope
→ Administrative Record Service
→ Record Store

Application Principal Context
→ Record Policy
→ Application Record Service
→ Record Store
```

约束：

- Admin / Agent Principal 永远不映射为业务 `auth.id`；
- Record Policy 不替代 Capability Scope；
- Control Plane API Key 不得成为绕过 Record Policy 的 Application credential；
- 不新增 test-only HTTP Auth header/token；
- Normal/Auth Collection 的业务 Record 共用同一 Record Store。

## 6. Record Store 与 Schema 权威

### 6.1 单一 Record Store

V0.1.0 只有一套生产 Record Store。

禁止引入：

- 通用 `DatabaseAdapter`；
- ORM Provider Framework；
- 第二套 Record Runtime；
- Auth Collection 专用业务 Record Store。

SQLite-specific 实现可以存在于 SQLite Runtime Store 内部，但不能泄漏为公共 Backend Model/API 概念。

### 6.2 Runtime Backend Model 是 Schema 权威

Record Store 从当前 Runtime Backend Model 解析：

- Collection / Collection kind；
- Field / Field type；
- required；
- literal default；
- validation；
- Relation；
- softDelete；
- optimisticLock；
- Record Policy。

不得维护第二份可编辑 Schema Truth。

### 6.3 Normal / Auth Collection

Normal Collection 与 Auth Collection 的业务 Record 使用同一持久化、validation、query、policy 基础设施。

本阶段不实现：

- Auth login identity mapping；
- Password Credential；
- register/login/refresh/session runtime。

这些后续能力只能建立在同一 Auth Collection Record Store 之上，不能另建业务数据表模型。

## 7. Record 元数据

每个 Record 至少具有服务器维护的：

- `id`：UUIDv4；
- `createdAt`：UTC RFC3339；
- `updatedAt`：UTC RFC3339；
- `version`：仅 optimisticLock=true 时存在，从 `1` 开始；
- `deletedAt`：仅 softDelete=true 时内部维护。

规则：

- 普通 mutation payload 不允许写系统元数据；
- successful update 更新 `updatedAt`；
- successful optimistic update 的 version 精确 +1；
- restart 后 metadata 语义保持稳定。

---

## 8. Field 与 Validation 边界

### 8.1 本阶段先真实完成的 scalar Field

#67 首条 Record path 必须真实支持：

- `text`
- `integer`
- `number`
- `decimal`
- `boolean`
- `date`
- `datetime`
- `json`
- `select`
- `email`
- `url`

Backend authoritative validation 至少覆盖：

- unknown Field；
- required；
- type；
- declarative validation；
- literal default；
- select option；
- decimal precision/scale；
- system metadata readonly。

### 8.2 Relation Field

Relation 的公共模型已经冻结，但真实 Record relation persistence/integrity 不在 #67 假实现。

真实 Relation：

- write/read persistence；
- target integrity；
- Relation Options；
- `onDelete=restrict/setNull`；
- Relation Expand；
- relation expression resolution；

统一由 #72 在真实 relation state 上收口。

#68 只需要保证 delete orchestration 可扩展到同一 mutation seam，不允许使用 Mock Relation 数据证明生产 `onDelete` 已完成。

### 8.3 File Field

File Field 的 Backend Model/Frozen Contract 保持不变，但 committed File value 必须依赖后续 Basic Upload Session / File Runtime。

本阶段：

- 不伪造 committed FileValue；
- 不允许直接把任意字符串当 file reference；
- 不新增临时 file binding contract；
- Data Plane Core E2E 使用不要求 File Field 的 Collection。

File runtime 后续必须接入同一 Record mutation lifecycle。

### 8.4 Literal Default

Create：缺失 Field 且声明 default 时由 Backend 应用。

Update：omitted Field 保留旧值，不重新应用 create default；omitted 不等于 null/reset/default。

## 9. Unified Expression Engine

### 9.1 一个语言

以下能力共享：

- Data API Filter；
- Record Policy；
- Administrative Data Query Filter；
- 后续 Realtime Subscription Filter。

共享执行模型：

```text
Parser
→ AST
→ Name Resolution
→ Type Checking
→ Canonical Evaluation
→ SQLite Predicate Compilation
```

禁止 caller expression 直接拼接 SQL；SQLite compiler 只接收 resolved/typed AST，并使用参数化查询。

### 9.2 V0.1 运算符

支持：

- `==`, `!=`
- `<`, `<=`, `>`, `>=`
- `&&`, `||`, `!`
- `null` comparison
- `contains`
- `in` against literal list
- scalar Field access
- single Relation one-level Field access
- many Relation ID membership through `contains`
- `auth`, `record`, `before`, `after` context

不支持：arbitrary JavaScript、raw SQL、任意数据库函数、user-defined function、recursive/deep relation traversal。

### 9.3 分阶段接线

#69 必须完成 scalar expression 的真实 parser/type/evaluator/SQLite compiler 与 Admin query。

Relation expression 的语法和类型规则在 #69 固定，但真实 relation storage/resolution 由 #72 接通；禁止通过 Mock Relation fixture 冒充 production completion。

### 9.4 NULL / Type

- 不使用 JavaScript loose equality/truthiness；
- null ordering 不通过隐式转换变成 true；
- unknown Field 是 validation error，不是 `undefined`；
- 不兼容 operator/type 在执行前拒绝；
- canonical evaluator 与 SQLite compiler 对支持表达式语义一致。

Expression parse/resolve/type/compile/evaluate failure 必须结构化失败；Policy 必须 fail closed。

---

## 10. Query Engine

Administrative 与 Application query 共用 Unified Expression Engine。

Application list 最终条件：

```text
caller filter
AND list Policy
AND view Policy
AND not-soft-deleted constraint
```

List Policy 必须下推真实 SQLite query path，不允许先全表 materialize 再在 JavaScript 内授权过滤。

### Sort

- Field 必须通过 Runtime Backend Model 解析；
- unknown Field 结构化拒绝；
- 支持升/降序；
- 必须有稳定 tie-breaker；
- 不把 SQLite 偶然默认顺序当公共语义。

### Pagination

Application API：

- `page >= 1`；
- `perPage` 默认 30；
- `perPage` 最大 100。

`totalItems/totalPages/items` 在 Filter + Policy + soft-delete 之后计算，未授权 rows 不进入 total。

---

## 11. Record Create

```text
Resolve Collection
→ Validate input names/types
→ Apply literal defaults
→ Build final candidate
→ Validate final candidate
→ [Application] create Policy(after)
→ Persist transactionally
→ [Administrative] durable Audit
```

Lifecycle Hook 不在本阶段实现，但 mutation pipeline 必须保留 future `beforeCreate` → final validation → Policy(final after) 的插入点。

---

## 12. Record Update

PATCH 是 partial mutation：

```text
persisted before + explicit patch = candidate after
```

Application update 顺序：

```text
load before through non-leaking path
→ update Policy(before)
→ build after
→ validate after
→ update Policy(after)
→ optimistic-lock guarded persist
```

before/after 两侧均必须允许。

Lifecycle Hook 不在本阶段实现，但 future `beforeUpdate` 必须接入同一 mutation pipeline。

---

## 13. Record Delete / Soft Delete

Application delete Policy 对 `before` 求值。

授权后：

- softDelete=false → physical delete；
- softDelete=true → 设置逻辑删除状态。

普通 Application list/view/relation expand 默认不返回 soft-deleted Record；Data Plane 无 `includeDeleted` escape hatch。

Administrative Data Access 按 Frozen Contract 处理 deleted Record。

#68 完成基础 delete/soft-delete 与统一 deletion orchestration；真实 Relation `restrict/setNull` 在 #72 有真实 relation state 后验收。

---

## 14. Optimistic Lock

optimisticLock=true 时：

- create version=1；
- read 返回 version；
- PATCH/DELETE 要求 Frozen `If-Match` / expectedVersion；
- mismatch → `409 OPTIMISTIC_LOCK_CONFLICT`；
- successful update version +1；
- stale mutation 不修改 Record/version/updatedAt/relation state。

乐观锁必须作为数据库 mutation 原子条件，禁止“先 SELECT version、应用层比较、再无条件 UPDATE”。

---

## 15. Record Policy Runtime

Application Data Plane deny by default。

分别支持：`list/view/create/update/delete`。

Administrative Data Access 不运行 Record Policy。

### list

返回 row 必须同时满足 list + view + caller Filter + soft-delete constraint，并在 SQLite query path 执行。

### view

对 persisted Record 求值。Unauthorized 与 nonexistent 对普通 caller 使用 non-leaking Frozen `NOT_FOUND` 语义。

### create

对 authoritative default/validation 后的 final `after` candidate 求值。

### update

同一 update Policy 对 `before` 和最终 `after` 各执行一次，两侧都必须通过。

### delete

对 persisted `before` 求值。

### fail closed

任何 parse/resolve/type/compile/evaluate failure 不允许 accidental allow。

---

## 16. Application AuthContext 测试边界

本 Data Plane Core 阶段不实现 Application register/login/session runtime。

因此必须严格区分：

1. **Unauthenticated HTTP**：可直接通过真实 `/api/v1/*` HTTP seam 验证 `auth.id=null / auth.collection=null` 下的 Policy 行为；
2. **Authenticated Policy**：在真实 Application Record Service + real SQLite seam 中注入显式 synthetic Auth Principal context 验证；
3. 如果现有 composition 已有不改变公共 Contract 的内部 AuthContext resolver seam，可用该内部 seam 提升集成层级；
4. 禁止新增 test-only HTTP header、临时 token scheme、未冻结 cookie、Control Plane API Key shortcut。

后续 Application Auth Runtime 只负责把 Frozen Bearer/session identity 解析为既有 AuthContext，不重新实现 Record Policy。

未登录请求中的 `auth=null` 不等于 V0.1.x Anonymous Principal 产品能力。

---

## 17. Relation

### identity

Relation 使用稳定 target Record ID，不使用 display value 作为身份。

### write

Application relation write：target 必须存在并对当前 Auth Principal 可 view；forbidden/nonexistent 不得形成 existence oracle。

Administrative relation write：使用 Administrative capability，不运行 Record Policy。

### onDelete

仅支持冻结的 `restrict | setNull`。

- one `setNull` → 清空引用；
- many `setNull` → 从 relation set 移除 target identity；
- cascade delete 不支持。

真实 onDelete 必须在 #72 的真实 relation state 上验收，不允许用 Mock relation fixture 证明 production behavior。

### options

Admin Relation selector 从真实 Administrative Record Query 派生 target identity + display data；不建立专用 Relation Options 存储或第二数据源。

### expand

最大深度 2。

每个 target 独立执行目标 Collection `view` Policy：

- denied one → expanded value `null`；
- denied many → 省略 denied entries。

Parent 可见不代表 target 可见。

## 18. Administrative Data Access

使用 Frozen Control Plane namespace：

```text
/_modelry/api/v1/data/...
```

规则：

- read/query → `data:inspect`；
- create/update/delete → `data:mutate`；
- 每次 Administrative Data Access 形成 durable Audit Fact；
- actor 使用真实 Admin/Agent Principal；
- 不映射为 `auth.id`；
- 不运行 Record Policy；
- 使用同一 Backend validation / Record Store / Query Engine / optimistic-lock / soft-delete 语义。

大查询 Audit 记录有界 query intent/result count，不复制完整 payload。

---

## 19. Application Data API

沿用 Frozen routes：

```text
GET    /api/v1/collections/:collection/records
POST   /api/v1/collections/:collection/records
GET    /api/v1/collections/:collection/records/:id
PATCH  /api/v1/collections/:collection/records/:id
DELETE /api/v1/collections/:collection/records/:id
```

List query：`filter/sort/page/perPage/expand`。

不增加 PUT、SQL endpoint、GraphQL、OData、第二套 query language。

Authenticated transport 的真实 Bearer/session 接线属于后续 Application Auth Runtime；本阶段不得为测试修改 Frozen Contract。

## 20. Frontend / Admin 接线

现有 Frontend `RecordRepository` 是 Frozen 边界，不重新设计。

Production 最终从：

```text
Records UI → Mock Record Repository
```

切换为：

```text
Records UI
→ Control Plane Administrative Record Repository
→ HTTP
→ Backend Application Service
→ SQLite
```

必须最终删除：

- Record list 的 `NOT_FOUND -> fabricated []`；
- Production CRUD 对 Mock Record Repository 的依赖；
- `recordService` 对 Mock Collection fixture 的生产依赖；
- Relation Options 对 Mock Records 的依赖。

对应真实能力未完成前可以明确 deferred，但不得伪装为空数据或成功。

---

## 21. Transaction 边界

单次 Record mutation 不得暴露部分状态。

需要原子一致的同步 durable state 至少包括：

- Record mutation；
- version/timestamps；
- soft-delete state；
- 已实现阶段的 relation state；
- Administrative mutation 所需 Audit durability。

不得出现“mutation 失败但 Audit 宣称成功”或“mutation 成功但 required Audit 丢失”。

未来 File / Lifecycle Hook / Domain Event / Realtime 必须接入同一 mutation lifecycle，不允许再造第二套 Record mutation engine。

## 22. 测试策略

### Administrative HTTP

### Application Policy

- unauthenticated path：真实 HTTP；
- authenticated path：真实 Application Service + real SQLite + synthetic AuthContext；

→ Update
→ Filter

### Contract Regression

Frozen Contract / OpenAPI / Manifest / Repository Mapping 无未授权 drift。

### CI
