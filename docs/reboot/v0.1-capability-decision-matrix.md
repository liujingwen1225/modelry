## Key conflicts resolved for the next drafting pass

1. **Bun vs Go**  
   Go wins. Bun ADR/spike becomes archive-only.

2. **TypeScript Hook vs Go core**  
   Hook product capability stays; implementation is redesigned around an embedded JavaScript extension runtime rather than Go plugins.

3. **Old Admin “no global API” vs latest Admin V2**  
   Latest Admin V2 / Global API planning wins: a top-level Application API workspace is part of the current product direction.

4. **Relations / Indexes as separate Collection pages vs Schema local views**  
   Latest Admin V2 wins: merge them into Schema.

5. **Old broad Auth ADR vs later V0.1.0 runtime scope**  
   Reboot should start from the smaller working V0.1.0 auth set and preserve expansion compatibility.

6. **Old Frozen Contract vs Reboot Contract First**  
   Old contract is a reference baseline. The new contract must be reviewed and frozen before Go implementation.

## Proposed first freeze candidate

The first new `docs/01-v0.1-scope.md` should probably make V0.1.0 succeed when this closure works:

```text
run modelry
→ bootstrap/login Admin
→ create Normal/Auth Collection
→ define Schema / Relation / Index / Policy
→ Review ChangeSet / Diff / Risk
→ Apply / Migration
→ create/query durable Records
→ Application register/login
→ use REST/OpenAPI
→ upload/bind Local File
→ execute Lifecycle JS Hook
→ observe SSE Realtime
→ inspect Global/Collection API
→ inspect Request Logs (if kept in V0.1.0)
→ inspect Audit/Activity
→ Agent inspects/proposes/applies allowed change through MCP
→ restart
→ durable state, migration history and contract remain consistent
```

The one scope item that deserves an explicit yes/no before Scope freeze is **Request Logs in V0.1.0 vs V0.1.x**. Everything else above has a stronger existing baseline.
