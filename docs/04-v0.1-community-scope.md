# Modelry V0.1 Community 范围

## 目标

V0.1 需要证明 Modelry 是一个真正好用、完整、可发布的 Community Backend Platform。

成功标准：

> 开发者可以从空目录开始，通过一个统一产品完整完成 Model → Data → Secure → API → Observe → Evolve，并在 Reload / Restart 后验证 Durable Result。

## 固定技术基线

- Go
- SQLite Only
- React + TypeScript + Vite
- Modular Monolith
- Contract First
- Zero-config-first
- 简单 Self-hosted Delivery
- One Runtime / One Project

PostgreSQL、Commercial / Enterprise 与 Cloud 不进入 V0.1 Implementation Scope。

# KEEP — V0.1 必须完成

## 1. First Run / Owner

必须支持：

- 合法空目录直接启动；
- 本机首次访问不要求复制长 Setup Token；
- 创建第一个 Owner；
- Bootstrap Capability 自动关闭；
- Restart 后 Durable State 保持；
- Partial / Invalid Initialization 有恢复建议；
- 首次完成 Setup 且没有 Collection 时直接进入 Create Collection。

V0.1 只要求一个 Owner。

Additional Administrator Management 进入 V0.1.x。

## 2. Collections / Schema

必须支持：

- Normal Collection
- Auth Collection
- Fields
- Relations
- Basic Index / Unique
- Validation
- Defaults

系统字段固定：

~~~text
id
createdAt
updatedAt
~~~

V0.1 中全部存在、显示、锁定，不允许删除或改名。

常见 Unique 作为 Field Feature 暴露；Composite / advanced index 仍可从 Indexes 视图管理。

## 3. Records

必须支持：

- Create
- View
- Update
- Delete
- Search / Filter / Sort
- Pagination
- Relation Value / Expand
- Single File Value
- Deep Link
- Context Preservation
- Reload 后 Durable Result 保持

无 Bulk Runtime 时不显示 Row Selection / Bulk Action。

## 4. Schema Pending Changes

Backend Model Mutation 底层统一经过：

~~~text
ChangeSet
→ Structured Diff
→ Risk / Preconditions / Impact
→ Apply Attempt
→ Migration History
~~~

产品 UX：

~~~text
edit Field / Relation / Index
→ durable Pending Change
→ continue modeling
→ Apply N changes
→ risk confirmation only when required
→ Applied / Failed
~~~

要求：

- 单 Collection Scope；
- Fields / Relations / Indexes 共用一个 Schema Pending Draft；
- Pending Operation 一旦保存即耐久；
- 切换页面 / Refresh 不丢失；
- 不需要 Save for Later；
- SAFE change 直接 Apply；
- Risk change 当前页面 Review / Confirm；
- Failed Apply 可恢复；
- Applied History 可验证；
- 不把 Policy / Auth Configuration 混进 Schema Draft。

## 5. Application API

必须包含：

- REST Application API
- OpenAPI
- Collection API Workspace
- Global API Workspace
- Endpoint Discovery
- API Runner
- Structured Error
- Canonical requestId
- Request Logs

Runner 结果必须显示：

- status
- duration
- requestId

失败时直接提供 **View request details**，不要求用户再去 Requests 搜索 requestId。

## 6. Application Auth

V0.1 至少支持：

- Auth Collection
- Email + Password
- Server-revocable Session
- Session Management

创建 Auth Collection 时：

- email 是 Required + Unique Auth Identifier；
- password 是 Credential，不是 Field；
- Self Registration 默认 Disabled；
- 用户可在创建时直接开启；
- Authentication Runtime 创建完成后即可使用。

Admin 手工创建 App User 时，必须在一个产品操作中同时完成：

~~~text
Profile Record
+
Password Credential
~~~

不得要求先建 Record，再去另一页创建 Credential。

## 7. Access Rules

至少覆盖：

- list
- view
- create
- update
- delete

默认 Fail Closed。

UI 优先提供：

- No access
- Anyone
- Signed-in users
- Record owner
- Custom rule

Custom Expression 是 Advanced Surface。

V0.1 不要求 Hypothetical Policy Simulation Engine。

用户可通过真实 API Runner + Request Detail 验证 Allow / Deny。

## 8. Files

V0.1：

- Local Storage
- Single File Field
- File Size Constraint
- MIME Constraint
- Upload Lifecycle
- Temporary / Unbound Cleanup Rule

Multiple File Values 与 S3-compatible Storage 进入 V0.1.x。

## 9. Access / Service Account

必须支持：

- Current Owner
- Service Account
- Permission
- API Key
- One-time API Key Reveal
- Disable / Revoke

UI 不暴露 Principal / Capability / Credential 作为普通用户主术语。

V0.1 不要求新增多个 Administrator。

## 10. Observability

### Requests

记录 Application HTTP Metadata：

- requestId
- endpoint
- method
- status
- duration
- time
- auth / authorization outcome where safe

禁止无边界记录：

- Raw Credential
- Raw Authorization Header
- Full Sensitive Body
- Unrestricted Raw Header

### Audit

保存 Security / Governance Durable Fact。

### Overview / Contextual Diagnostics

展示：

- Runtime health
- Storage health
- Pending / Failed Change
- actionable runtime problem

V0.1 不实现独立 Generic Activity Timeline。

## 11. Settings

V0.1 Settings 以诊断和只读信息为主：

- Runtime
- Storage

每项必须明确：

- current state
- source
- health
- restart guidance when relevant

完整 Editable Runtime Settings 延后。

## 12. MCP

Core MCP 是一等 Machine Interface。

它必须遵守同一套：

- Backend Model
- Change lifecycle
- Permission
- Access Rule
- Audit

不得拥有隐藏绕过能力。

V0.1 只实现支持核心闭环所需的最小 Tool Set。

## 13. CLI

保留启动、状态、诊断和核心管理所需最小 CLI。

不为了 CLI 复制第二套产品语义。

# SIMPLIFY — V0.1 刻意收敛

- id / createdAt / updatedAt 固定存在；
- Unique 优先作为 Field Feature；
- Files 仅 Local + Single Value；
- Policy 使用 Preset-first；
- Access 只有 Owner + Service Accounts；
- Settings 以 Read-only / Diagnostic 为主；
- Observability 使用 Overview + Requests + Audit；
- Changes 主 UI 使用 Pending / Needs review / Failed / Applied；
- Technical ChangeSet / Apply Attempt / Migration 进入 Technical Details。

# ACCEPTED — Community V0.1.x

下列能力已由 Community V0.1.x 交付，并通过真实 Runtime、真实 SQLite、真实 HTTP 与真实 Chromium 验收。它们是当前权威语义，不再是推迟项：

- SSE Realtime（#21）
- Lifecycle Hooks / JS · TS Extension Runtime / Secrets UI（#23）
- Event Hooks / Webhooks / Simple Cron · Jobs（#24）
- Multiple File Values / S3-compatible Storage（#25）
- Additional Administrator Management / Password Reset · Email Verification Delivery（#26）
- Policy Simulation / Generic Activity Timeline / Full Drift Detection Product / Editable Runtime Settings（#27）
- Typed Custom Application API / SDK Generation / Import · Export / Full Backup · Restore UX（#28）

与之配套的合同是
[ADR-0002](adr/0002-durable-record-events.md)、[ADR-0003](adr/0003-extension-runtime-lifecycle-secrets.md)、
[ADR-0004](adr/0004-local-webhook-delivery-and-cron.md)、[ADR-0005](adr/0005-file-values-and-storage-providers.md)、
[ADR-0006](adr/0006-administrators-and-account-recovery.md)、[ADR-0007](adr/0007-policy-activity-drift-and-settings.md)、
[ADR-0008](adr/0008-backup-restore-import-export-and-generated-artifacts.md) 及 Spec 0004–0010。

Community V0.1.x 仍然只使用 SQLite、单个 Runtime、单个 Project。上述任何能力都不要求 PostgreSQL、Cloud Control Plane 或 Enterprise 组件。
