# Modelry V0.1 Community 范围

## 目标

V0.1 需要证明 Modelry 是一个真正可用的产品，而不仅仅是 Runtime + Admin UI。

成功标准：

> 一个开发者可以从空项目开始，通过一个统一产品完整构建并运行一个小型真实应用后端。

## 固定技术基线

- Go
- SQLite Only
- React + TypeScript + Vite
- Modular Monolith
- Contract First
- Zero-config-first Startup
- 简单 Self-hosted Delivery

PostgreSQL、Commercial / Enterprise 和 Cloud 均不进入 V0.1 Implementation Scope。

## 1. First Run

必须支持：

- 在合法空目录中直接启动并完成安全初始化；
- 清晰完成第一个 Admin Bootstrap；
- Restart 后 Durable State 保持；
- Partial / Invalid Initialization 返回可操作恢复建议。

## 2. Collections / Schema

必须包含：

- Normal Collection
- Auth Collection
- Fields
- Relations
- Indexes / Unique
- Validation
- Defaults

Schema 是 Collection 内统一 Workspace：

~~~text
Schema
├── Fields
├── Relations
└── Indexes
~~~

## 3. Records

必须支持：

- Create
- View
- Update
- Delete
- Filter
- Sort
- Pagination
- Relation Expand
- File Value
- Reload 后 Durable Result 仍存在

Records 是 Collection 默认页面。

## 4. Changes

Backend Model Mutation 统一使用：

~~~text
Draft / Proposal
→ ChangeSet
→ Structured Diff
→ Risk + Preconditions + Impact
→ Apply Attempt
→ Migration History
~~~

高风险操作需要 Explicit Confirmation。

失败必须保持 Runtime 可诊断、可恢复。

## 5. Application API

必须包含：

- REST Application API
- OpenAPI
- Collection API Explorer / Runner
- Global API Workspace
- Endpoint Discovery
- Structured Error
- Canonical requestId

Global API：

~~~text
API
├── Endpoints
└── Requests
~~~

## 6. Application Auth

V0.1 至少支持：

- Auth Collection
- Email + Password
- Server-revocable Session
- Session Management

Username、OAuth 等能力后续单独评估。

## 7. Record Policy

Policy 至少覆盖：

- list
- view
- create
- update
- delete

默认 Fail Closed。

必须有可用的 Policy Editor 和 Diagnostic / Simulation Experience，让用户知道为什么被允许或拒绝。

## 8. Files

必须包含：

- File Field
- Local Storage
- Single / Multiple Value（按 Contract 定义）
- File Size Constraint
- MIME Constraint
- Upload Lifecycle
- Temporary / Unbound Cleanup Rule

## 9. Realtime

- SSE-based Realtime
- Policy-aware Subscription
- Best-effort Semantics

不承诺 Reliable Queue 或任意 History Replay。

## 10. Hooks / Secrets

### Lifecycle Hook

要求：

- JavaScript / TypeScript-facing Authoring Experience
- Controlled Runtime API
- Timeout
- Error Isolation
- Hook Failure 不得 Crash Runtime

同步 Lifecycle Hook 用于：

- Validation
- Deterministic Field Mutation
- Reject Mutation

不可回滚 External Side Effect 不属于同步 Pre-commit Hook 语义。

### Secrets

Secret 是一等 Control Plane Resource。

- 可 Create / Replace / Delete
- 可查看 Name / Presence / Metadata
- 普通管理接口不重新读取 Plaintext

## 11. Observability

### API Requests

记录 Application HTTP Metadata，例如：

- requestId
- Endpoint
- Method
- Status
- Duration
- Time

明确禁止无边界记录：

- Raw Credential
- Raw Authorization Header
- Full Sensitive Body
- Unrestricted Raw Header

### Audit

保存 Security / Governance Durable Fact。

### Activity

展示跨模块 Runtime / Migration / Hook 等 Operational Event。

三者必须分开。

## 12. Admin

一级导航：

~~~text
Core
  Overview
  Collections
  API

Control
  Changes
  Hooks
  Access

System
  Settings
  Activity
~~~

Collection Workspace：

~~~text
Records
Schema
Policy
Auth     <- Auth Collection only
API
~~~

Collections：

- Card View
- List View
- 默认 Card

## 13. MCP

MCP 是 Modelry 的一等 Machine Interface。

它必须遵守同一套：

- Backend Model
- ChangeSet
- Capability
- Policy
- Audit

不得拥有隐藏绕过能力。

具体 Tool List 在新的 Domain / HTTP Contract 稳定后再定义。

## V0.1 之后再做

优先进入 V0.1.x / Community Mature：

- OAuth
- Password Reset / Email Verification Delivery
- S3-compatible Storage
- Event Hook
- Webhook
- Simple Cron / Jobs
- 完整 Backup / Restore UX
- Typed Custom Application API
- SDK Generation
- Import / Export

## V0.1 明确非目标

- PostgreSQL
- Commercial / Enterprise Feature
- Cloud Control Plane
- GraphQL
- gRPC Data API
- Workflow / DAG
- Kubernetes-first
- Microservices
- HA Cluster
- Multi-project Runtime
- Hostile-code Serverless Sandbox
- Database Trigger / Stored Procedure Product Surface

## V0.1 Exit Criteria

Mandatory Browser Acceptance 必须证明：

~~~text
Functional Closure
+
UX Closure
+
Visual Closure
+
Error Closure
+
Business Flow Closure
+
Restart Persistence
+
Cross-Surface Durable Verification
~~~

否则不能仅以“测试通过”认定 V0.1 完成。
