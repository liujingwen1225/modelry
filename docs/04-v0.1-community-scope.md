# Modelry V0.1 / V0.1.x 交付范围

> 文件名继续保留 v0.1-community-scope，是为了保持历史链接稳定。本文件现在记录已经完成的 V0.1 与 V0.1.x 交付边界，不再代表旧的“社区版 → 企业版”路线。

## 当前状态

- V0.1 核心闭环：已完成；
- V0.1.x 产品成熟化 Goal #22：已完成并合入 main；
- 当前下一阶段：首次公开发布 / 开发者启用；
- 尚未交付但进入 V0.2 高优先级：应用 OAuth / OIDC。

## 技术基线

- Go
- SQLite
- React + TypeScript + Vite
- 模块化单体
- 契约优先
- 零配置优先
- 自托管
- 单运行时 / 单项目

SQLite 和单运行时 / 单项目是当前自托管 Modelry 的正式产品架构，不再描述为等待 PostgreSQL 或企业版替换的临时约束。

# 一、V0.1 核心能力 — 已交付

## 1. 首次运行 / 所有者

支持：

- 合法空目录直接启动；
- 本机首次访问不要求复制长 Setup Token；
- 创建第一个所有者；
- 初始化能力自动关闭；
- 重启后状态保持；
- 部分初始化 / 无效初始化有恢复建议；
- 首次完成设置且没有集合时直接进入创建集合。

V0.1 初始只要求一个所有者；V0.1.x 已增加多管理员能力。

## 2. 集合 / 结构

支持：

- 普通集合；
- 认证集合；
- 字段；
- 关系；
- 基础索引 / Unique；
- 校验；
- 默认值。

系统字段固定：

~~~text
id
createdAt
updatedAt
~~~

系统字段存在、显示、锁定，不允许删除或改名。

## 3. 记录

支持：

- 创建；
- 查看；
- 修改；
- 删除；
- 搜索 / 筛选 / 排序；
- 分页；
- 关系值 / 展开；
- 文件值；
- 深链接；
- 页面上下文保持；
- 刷新 / 重启后状态保持。

## 4. 结构待应用变更

底层统一经过：

~~~text
ChangeSet
→ Structured Diff
→ Risk / Preconditions / Impact
→ Apply Attempt
→ Migration History
~~~

这些名称属于已接受的内部 Domain 语义。

产品界面表现为：

~~~text
编辑字段 / 关系 / 索引
→ 保存耐久待应用变更
→ 继续建模
→ 一次应用多项变更
→ 必要时确认风险
→ 已应用 / 失败 / 恢复
~~~

要求：

- 单集合范围；
- 字段 / 关系 / 索引共用同一结构待应用草稿；
- 保存后即耐久；
- 页面跳转 / 刷新不丢失；
- 安全变更不增加无意义确认；
- 风险变更原地复核 / 确认；
- 失败后可恢复；
- 应用历史可验证；
- 策略 / 认证配置不混入结构草稿。

## 5. 应用 API

支持：

- REST API；
- OpenAPI；
- 集合 API 工作区；
- 全局 API 工作区；
- Endpoint 发现；
- API 调试；
- 结构化错误；
- 统一 requestId；
- 请求日志。

请求结果至少展示：

- 状态；
- 耗时；
- requestId。

失败时可直接进入对应请求详情。

## 6. 应用认证

支持：

- 认证集合；
- 邮箱 + 密码；
- 服务端可撤销会话；
- 会话管理；
- V0.1.x 密码重置和邮箱验证通知。

创建认证集合时：

- email 是必填且唯一的认证标识；
- password 是凭证，不是普通字段；
- 自助注册默认关闭，可显式开启。

Admin 创建应用用户时，一次完成：

~~~text
Profile Record
+
Password Credential
~~~

底层继续保持记录与凭证分离。

## 7. 访问规则

覆盖：

- list
- view
- create
- update
- delete

默认拒绝访问。

界面优先提供：

- 无访问权限；
- 任何人；
- 已登录用户；
- 记录所有者；
- 自定义规则。

V0.1.x 已交付策略模拟。

## 8. 文件

V0.1 初始支持：

- 本地存储；
- 单文件字段；
- 文件大小 / MIME 类型约束；
- 上传生命周期；
- 临时 / 未绑定文件清理。

V0.1.x 已增加：

- 多文件值；
- S3 兼容存储；
- 存储提供方迁移。

## 9. 管理员 / 服务账号

支持：

- 所有者；
- 多管理员；
- 服务账号；
- 权限；
- API Key；
- API Key 仅显示一次；
- 停用 / 撤销。

普通界面不要求用户理解 Principal / Capability / Credential 等内部术语。

## 10. 可观测性 / 运维

### 请求日志

安全记录应用 HTTP 元数据：

- requestId；
- endpoint；
- method；
- status；
- duration；
- time；
- 安全范围内的认证 / 授权结果。

禁止无边界记录原始凭证、完整 Authorization Header 和敏感请求体。

### 审计

保存安全 / 管理相关的耐久事实。

### 活动记录

V0.1.x 已交付由各子系统事实组成的有边界活动时间线。

### 漂移检测

V0.1.x 已交付已应用模型、SQLite 物理投影与运行时管理状态之间的漂移检测和校准。

### 运行时设置

V0.1.x 已从只读诊断扩展到可编辑运行时设置。

# 二、V0.1.x 成熟化能力 — 已交付

## 11. 实时订阅

已交付 SSE 实时订阅，包括：

- 耐久 Record Event；
- 集合范围游标；
- 投递时权限校验；
- 重连 / 续传；
- 有边界的连接生命周期。

具体语义以 ADR-0002、Spec 0004 和 realtime HTTP contract 为准。

## 12. 扩展 / 密钥 / 自动化

已交付：

- JavaScript / TypeScript 扩展运行时；
- 生命周期钩子；
- 密钥配置；
- 事件钩子；
- Webhook；
- 定时任务 / Cron。

安全与外部副作用语义以 ADR-0003、ADR-0004 和对应 Spec 为准。

## 13. 可迁移能力 / 开发接口

已交付：

- 导入 / 导出；
- 完整备份 / 恢复；
- 类型化应用 API；
- SDK 生成；
- CLI；
- MCP。

MCP 是一等编码智能体接口，必须遵守同一套后端模型、变更生命周期、权限、访问规则和审计。

## 14. Admin 产品成熟化

已交付：

- 中文 / 英文；
- 命令面板；
- 顶部主题切换；
- 跨页面国际化；
- 浏览器 / 升级 / 重启 / 恢复闭环。

# 三、V0.1.x 已接受契约

已交付语义由以下文档冻结：

- ADR-0002 Durable Record Events
- ADR-0003 Extension Runtime / Lifecycle / Secrets
- ADR-0004 Local Webhook Delivery / Cron
- ADR-0005 File Values / Storage Providers
- ADR-0006 Administrators / Account Recovery
- ADR-0007 Policy / Activity / Drift / Settings
- ADR-0008 Backup / Restore / Import / Export / Generated Artifacts
- Spec 0004–0010
- 对应 HTTP Contract / OpenAPI

这里保留正式英文名称，是为了与仓库中的既有 ADR / Spec 一一对应。

这些文档记录已经交付的 Domain / Contract，不因为产品未来路线调整而失效。

# 四、V0.1.x 尚未交付

目前最主要的应用开发能力缺口：

- 应用 OAuth / OIDC Provider 与外部身份联合登录。

新路线将 GitHub / Google 应用 OAuth 作为 V0.2 高优先级能力。

这里的应用 OAuth 不等于：

- Modelry Admin 企业单点登录；
- SAML / SCIM；
- 组织身份。

# 五、V0.1 系列明确非目标

以下没有进入 V0.1 / V0.1.x：

- PostgreSQL；
- 组织 / 团队治理；
- 企业单点登录；
- 复杂企业 RBAC；
- 云端托管层；
- GraphQL；
- gRPC Data API；
- 工作流 / DAG 平台；
- Kubernetes 优先；
- 微服务；
- HA 集群；
- 多项目运行时；
- 不可信代码 Serverless 沙箱；
- 数据库触发器 / 存储过程产品界面。

其中企业和分布式基础设施项也不再自动属于“下一阶段”。是否进入未来路线必须依据真实用户需求重新决策。

# 六、V0.1 系列验收结论

V0.1 系列真实浏览器验收已经证明：

~~~text
首次运行
→ 建模
→ 数据
→ 安全
→ API
→ 观察
→ 演进
→ 重启
→ 验证耐久状态
~~~

并覆盖：

~~~text
功能闭环
+
体验闭环
+
视觉闭环
+
错误闭环
+
业务流程闭环
+
跨界面验证
~~~

后续版本不需要重新证明“Modelry 是否具备完整后端基础”，重点转向采用速度、开发效率和编码智能体体验。
